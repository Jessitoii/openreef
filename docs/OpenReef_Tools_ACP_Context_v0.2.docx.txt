It decides what the model sees on every inference call: which memories, which conversation history, which tool results, and what system prompt additions. Directly ported and adapted from OpenClaw's Context Engine architecture.▸ C.1 — Context Engine LifecyclePhaseWhen CalledWhat It DoesINGESTNew message added to sessionIndex message in sqlite-vec; update token count; tag with metadataASSEMBLEBefore each LLM inference callBuild ordered message list within token budget. Retrieve relevant memories. Inject system prompt additions.COMPACTContext window full OR /compact commandSummarize old messages into compact block. Preserve recent N turns verbatim.AFTER TURNAfter LLM response completesExtract and persist new memories. Update indexes. Trigger background consolidation if needed.▸ C.2 — Assemble Pipeline (per inference call)ContextEngine.assemble(sessionId, userMessage, tokenBudget):  Step 1: SYSTEM PROMPT CONSTRUCTION    ├── Agent persona block (identity, capabilities)    ├── Active skills injection (SKILL.md contents)    ├── User profile block (name, preferences, language)    ├── Available MCP tools block (connected servers)    ├── Active sub-agent status (if any running)    └── Dynamic memory hint  Step 2: MEMORY RETRIEVAL    ├── Embed userMessage → MiniLM on-device    ├── sqlite-vec cosine query → top-k=5 long-term memories    ├── Recent facts from short-term store (last 24h)    └── Inject as [MEMORY CONTEXT] block  Step 3: CONVERSATION HISTORY    ├── Count tokens in [SYSTEM] + [MEMORY]    ├── Remaining budget → fill with recent turns (newest first)    ├── If compacted summary exists → inject before recent turns    └── Tool call results pruned if older than N turns  Step 4: ASSEMBLE RESULT    └── Return { messages[], systemPromptAddition, estimatedTokens }▸ C.3 — Compaction StrategyWhen context window is approaching limit, the engine compacts old history into a summary block. Replace [old turns] with compact summary block  4. [recent 8 turns] always kept verbatim  5.
